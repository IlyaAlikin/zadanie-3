# Карта: геолокация и уведомления (Задание 3)

Это продолжение заданий 1 и 2. Метки и изображения по-прежнему хранятся в SQLite. В этом задании добавлены:

- **отслеживание местоположения** в реальном времени: точка пользователя на карте и кнопка «ко мне»;
- **локальные уведомления** при приближении к сохранённым меткам, без дублей и с автоматической очисткой при выходе из зоны;
- **режим симуляции GPS** для тестирования прямо на телефоне.

## Стек

- Expo SDK 58, React Native 0.88, TypeScript (strict)
- `expo-router`, `react-native-maps`, `expo-image-picker`
- `expo-sqlite`, `expo-file-system` (из задания 2)
- **`expo-location`**: геолокация
- **`expo-notifications`**: локальные уведомления

## Настройка и запуск

Нужно:

- Node.js **22.13 или новее** (версия указана в `.nvmrc`);
- приложение **Expo Go** на телефоне. В Expo Go и в Expo CLI нужно войти под одним аккаунтом Expo.

```bash
git clone <url-репозитория>
cd zadanie-3-geo
nvm use
npm install
npx expo login       # один раз
npx expo start       # отсканировать QR-код в Expo Go
```

При первом запуске приложение попросит доступ **к геолокации** («при использовании приложения») и **к уведомлениям**.

Проверки:

```bash
npm run typecheck
npm run lint
```

## Как это работает

### Отслеживание местоположения (`services/location.ts`)

1. `requestLocationPermissions()` сначала проверяет текущий статус разрешения и только потом запрашивает. Если пользователь отказал, функция бросает `LocationServiceError` с типом `PERMISSION_DENIED` (можно спросить ещё раз) или `PERMISSION_BLOCKED` (доступ возможен только через настройки).
2. `ensureLocationServicesEnabled()` проверяет, включён ли GPS. На Android функция пробует показать системный диалог включения. Если GPS так и не включён, ошибка получает тип `SERVICES_DISABLED`.
3. Чтобы точка появилась быстрее, сразу показывается последнее известное местоположение (`getLastKnownPositionAsync`).
4. `startLocationUpdates()` подписывается через `watchPositionAsync` с параметрами `LocationConfig`: точность `Balanced`, обновление раз в 5 секунд или при сдвиге на 5 м. Ошибки провайдера приходят в отдельный обработчик.
5. При размонтировании провайдера подписка снимается (`subscription.remove()`).
6. Когда приложение возвращается из фона (`AppState` переходит в `active`), отслеживание перезапускается, если до этого была ошибка. Так приложение подхватит разрешение или GPS, которые пользователь включил в настройках.

Расстояние считается функцией `calculateDistance()` по **формуле гаверсинусов** (радиус Земли 6 371 км) и возвращается в метрах.

### Проверка приближения (`services/proximity.ts`)

При каждом обновлении координат, а также при добавлении или удалении метки (через `dataVersion`), вызывается `checkProximity()`:

| Расстояние до метки | Действие |
|---|---|
| ≤ **100 м** (`PROXIMITY_THRESHOLD`) | `showNotification(marker)` |
| > **130 м** (`EXIT_THRESHOLD`) | `removeNotification(marker.id)` |
| от 100 до 130 м | состояние не меняется |

Показания с погрешностью хуже **200 м** (`MAX_ACCEPTABLE_ACCURACY`) для проверки зон не используются, иначе неточный GPS давал бы ложные срабатывания.

## Стратегия управления уведомлениями

Логика находится в классе `NotificationManager` (`services/notifications.ts`). Его структура взята из ТЗ и доработана.

1. **Хранение в памяти.** Хранилище — `Map<markerId, ActiveNotification>`, где запись имеет вид `{ markerId, notificationId, timestamp }`. Пока метка есть в этой `Map`, повторное уведомление для неё не создаётся.
2. **Предотвращение дублей:**
   - проверка `activeNotifications.has(marker.id)`;
   - **последовательная очередь операций**: все вызовы `show` и `remove` выполняются по одному. GPS может прислать два обновления быстрее, чем выполнится `scheduleNotificationAsync`. Без очереди обе проверки `has()` вернули бы `false`, и пользователь получил бы два уведомления. С очередью вторая проверка идёт после того, как первая операция записала уведомление в `Map`;
   - **гистерезис** 100/130 м: на границе зоны уведомление не появляется и не исчезает постоянно из-за погрешности GPS.
3. **Очистка при выходе из зоны.** Вызываются `cancelScheduledNotificationAsync` (если уведомление ещё не доставлено) и **`dismissNotificationAsync`**, который убирает уже показанное уведомление из шторки. Одного `cancelScheduled...`, как в примере из ТЗ, недостаточно: уведомление с `trigger: null` доставляется сразу, и `cancel` его из шторки не убирает.
4. **Удалённые метки.** После каждого изменения данных `syncWithMarkers()` убирает уведомления меток, которых больше нет в БД.
5. **Потеря доступа к геолокации.** Если геолокация стала недоступна, `clearAll()` убирает все уведомления, потому что определить зоны больше нельзя.
6. **Перезапуск приложения или устройства.** Состояние в памяти после перезапуска пустое. Поэтому при старте `dismissStaleNotifications()` убирает из шторки «наши» уведомления, оставшиеся с прошлого запуска. Их отличает метка `data.type = 'marker-proximity'`. Если пользователь всё ещё рядом с меткой, уведомление создастся заново при первом обновлении GPS. Так в шторке нет «сирот», и уведомления совпадают с тем, что приложение хранит в памяти.
7. **Уведомление при открытом приложении.** Обработчик `setNotificationHandler` показывает баннер и при открытом приложении. На Android используется отдельный канал `proximity` с высоким приоритетом.
8. **Нажатие на уведомление** открывает экран этой метки. Это работает и тогда, когда приложение было закрыто (`useLastNotificationResponse`).

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Отказ в доступе к геолокации | Красный баннер «Геолокация недоступна» с кнопкой **«Разрешить»** (повторный запрос). Если отказ окончательный, вместо неё кнопка **«Открыть настройки»**. Карта и метки работают, уведомления о зонах выключены |
| Выключен GPS | Баннер с кнопками «Открыть настройки» и «Повторить». На Android сначала показывается системный диалог включения |
| Ошибка провайдера во время слежения | Баннер с текстом ошибки. При возврате в приложение слежение перезапускается автоматически |
| Отказ в разрешении на уведомления | Жёлтый баннер «Уведомления выключены» с кнопкой «Разрешить» или «Открыть настройки» и кнопкой «Скрыть». Метки рядом всё равно показываются **внутри приложения**: в панели «Рядом с вами» и зелёным цветом зоны на карте |
| Ошибка API уведомлений | Ошибка логируется, очередь `NotificationManager` продолжает работать |
| Низкая точность GPS | Проверка зон пропускается до следующего точного показания |

## Инструкция по тестированию

### Способ 1. Встроенная симуляция GPS (работает на любом телефоне)

1. Поставьте метку долгим нажатием.
2. Нажмите кнопку **«Симуляция GPS»** внизу слева, она станет фиолетовой.
3. Нажмите на карту **внутри круга** метки. Фиолетовая точка переместится туда, появится уведомление «Вы рядом с меткой!», круг станет зелёным, а внизу появится панель «Рядом с вами».
4. Нажмите на карту ещё раз внутри круга. **Повторного уведомления не будет.**
5. Нажмите далеко от метки. Уведомление исчезнет из шторки, а панель «Рядом» скроется.
6. Снова нажмите внутри круга, и уведомление придёт снова.
7. Поставьте две метки рядом и нажмите между ними: придут **два** уведомления, по одному на каждую метку.

### Способ 2. Симуляция системными средствами

- **iOS Simulator:** меню *Features → Location → Custom Location…* (введите координаты метки) или готовые маршруты *City Run* / *Freeway Drive*.
- **Android Emulator:** *Extended controls (⋯) → Location*, где можно задать точку или загрузить маршрут GPX/KML.
- **Android-телефон:** *Настройки → Для разработчиков → Приложение для фиктивных местоположений*, затем выберите приложение для подмены GPS (например, *Fake GPS location*).
- **iPhone:** подключите его к Mac, в Xcode выберите *Debug → Simulate Location*.

### Сценарии из ТЗ

| Сценарий | Как проверить | Ожидаемый результат |
|---|---|---|
| Несколько меток одновременно | Две метки на расстоянии меньше 100 м, встаньте между ними | Два уведомления, в панели «Рядом» две строки |
| Выход и повторный вход | Уйдите дальше 130 м, затем вернитесь | Уведомление исчезает, затем приходит снова |
| Смена состояния приложения | Войдите в зону, сверните приложение, откройте шторку | Уведомление в шторке. Нажатие открывает экран метки |
| Перезагрузка с активными уведомлениями | Войдите в зону, закройте приложение или перезагрузите устройство, откройте снова | Старое уведомление убрано при старте. Если вы всё ещё в зоне, приходит одно новое |
| Отключённые службы геолокации | Выключите GPS и откройте приложение | Баннер «Службы геолокации выключены». После включения и возврата в приложение слежение запускается само |
| Отказ в разрешениях | Откажите в доступе к геолокации или уведомлениям | Соответствующие баннеры с действиями |
| Разная точность | Эмулятор позволяет задать точность | При погрешности больше 200 м зоны не пересчитываются |

В режиме разработки в консоль Metro пишутся логи `[Location]`, `[Notifications]` и `[DB]`.

## Известные ограничения

- **Нет отслеживания в фоне.** `watchPositionAsync` получает координаты, только пока приложение открыто. Для фона нужны `expo-task-manager`, `startLocationUpdatesAsync`, разрешение «Всегда» и development build: Expo Go на iOS фоновую геолокацию не поддерживает. Это сознательное ограничение, ТЗ требует обновления «пока приложение активно». Уже показанные уведомления остаются в шторке и после сворачивания приложения.
- **Активные уведомления хранятся только в памяти**, как требует ТЗ. После перезапуска состояние восстанавливается при первом обновлении GPS (см. пункт 6 стратегии).
- **Expo Go** поддерживает локальные уведомления, а push-уведомления на Android в нём недоступны начиная с SDK 53. В этом проекте push не используется.
- Радиусы зон (100 и 130 м) заданы константами и в интерфейсе не меняются.
- Точность в помещении может быть хуже 200 м. В этом случае проверка зон приостанавливается до появления точного сигнала.
- Режим симуляции влияет только на расчёт зон. Синяя системная точка на карте продолжает показывать реальное местоположение.
